# Report Blueprints

每次运行默认先选一个主蓝图。必要时可以叠加一个次蓝图，但必须写明理由。

## 1. Conversation / Roundtable / Podcast

适用：访谈、圆桌、播客、AMA、Q\&A、高密度对话视频。

强制要求：

- 先把表面问题改写成真正的工程问题、决策问题或机制问题
- 先做自然分段，再做章节组织
- 35--60 分钟内容默认拆成 8--12 个主题单元
- 正文至少要有一个导读节和一个最终行动/判断节
- 只要材料支持，至少要有 2 个形式化层输出，例如公式、成本模型、约束模型、决策流程图

常见失败：

- 写成“访谈复盘”而不是主题报告
- 全片只压成 5 个左右粗大章节
- `dialoguebox` 承担了正文主叙事

## 2. Lecture / Tutorial / Paper Explanation

适用：课程讲授、方法教学、论文讲解、公式推导、实验拆解。

强制要求：

- 问题定义和前置假设清晰
- 方法机制、公式、变量解释与例子必须成链
- 实验、局限、错误直觉与正确直觉要分开写
- 给出读者下一步如何复现、使用或辨别该方法的建议

常见失败：

- 只有白话总结，没有公式层
- 只有公式罗列，没有变量解释与直观含义
- 实验结论和方法机制没有联动

## 3. System / Product Architecture

适用：系统设计、架构讲解、产品技术拆解、工程复盘。

强制要求：

- 先明确业务目标，再讲架构
- 把模块边界、数据流、反馈链和失败点画出来
- 至少落一个指标模型：延迟、吞吐、成本、显存、稳定性、可观测性中的一种或多种
- 给出部署、演进或取舍建议

常见失败：

- 只说“系统很重要”，没有模块边界
- 只画图，没有指标和约束
- 只有架构描述，没有决策逻辑

## 4. Market / Career / Decision Analysis

适用：职业选择、方向下注、组织差异、市场判断、路径比较。

强制要求：

- 把“岗位名称”改写成“收益结构、约束结构和进入门槛”
- 至少显式比较反馈速度、竞争池、技术复利、ownership、风险暴露中的三项
- 至少给出一个判断框架、评分框架或决策流程
- 明确短期与中期的时间尺度，不要把所有判断揉成一个模糊建议

常见失败：

- 只讲个人感受，不建模
- 只给“看兴趣”这类空泛建议
- 没有区分短期可做与长期值得下注
